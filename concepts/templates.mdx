Hub ships templates for every common stack. Each one is a plain [cookiecutter](https://cookiecutter.readthedocs.io/) that renders into a fully wired project: `platform.toml`, code quality configuration, an `AGENTS.md`, tests, and a CI pipeline for your chosen provider. Pick a cloud overlay and a service, and the template composes them together before you write a single line of business logic.

## Cloud overlays

Cloud overlays layer deployment infrastructure on top of any compatible template. You choose a base template first, then add an overlay.

| Overlay | Compatible stacks | Adds |
|---------|-------------------|------|
| `aws/lambda` | Python | SAM template, HTTP API Gateway, custom domain config, deploy workflow, IAM policy |
| `aws/amplify` | Node.js | `amplify.yml`, security headers, start-job workflow, IAM policy |
| `docker` | Python, Go, Node.js | Language-appropriate `Dockerfile`, `docker-compose.yml` |

## What every template includes

Every template — regardless of type, stack, or overlay — ships the following:

- **`platform.toml`** — pre-filled with the project name, type, stack, template, language, and CI provider you chose
- **`.code_quality/`** — linter and formatter configuration for the stack
- **`AGENTS.md`** — instructions for AI coding agents working in the repository
- **Tests** — a minimal test suite that passes on a fresh project
- **CI file** — a workflow for your chosen CI provider (`github`, `gitlab`, `jenkins`, or `bitbucket`) that calls the shared [ci-scripts](https://github.com/actionplatform/ci-scripts)

## Adding your own templates

Any git repository can become a template source.

- **A plain repository** (a starter project, a reference service) becomes a single template. Hub detects the language from `pyproject.toml`, `go.mod`, `package.json`, and similar files, keeps any existing `platform.toml` (renaming the project), or adds `platform.toml`, `.code_quality/`, CI files, and hooks — exactly as `action-platform install` does.
- **A repository with an `index.json` at the root** becomes a full template catalog with the official layout (`projects/`, `cloud/`, `service/`).

To add a custom template source from the **CLI**:

```bash
action-platform init --source https://github.com/acme/templates.git@main
```

The `@ref` suffix is optional and accepts any branch, tag, or commit SHA.

To add one from the **web app**: go to **Templates → Template repositories → Add repository**, supply the name, git URL, and branch or tag. This option is available to owners and admins only. Private repositories are cloned using the organization's connected source host credentials.

Once added, every template, cloud overlay, and service from that repository appears in the web app's Templates catalog and the **Create project** wizard with its source labelled.

<Note>
Names are unique per organization and `official` is reserved for the built-in catalog. A repository that cannot be cloned appears as *Unavailable* with the error, without hiding the other sources.
</Note>

## List available templates

```bash
action-platform init --list
```

This lists all templates from the official catalog and any custom repositories your organization has added.
